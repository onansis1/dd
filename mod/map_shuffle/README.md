# 지도 건물 위치 섞기 (실험적)
`py -3 shuffle_map.py "<AssetBundles 경로>" [시드 | keep]`  (keep: 위치는 섞지 않고 해금만 적용) (게임/스팀 끄고 실행). 처음 실행할 때 data_levels.shufflebak 백업.
복원: data_levels.shufflebak 을 data_levels 로 덮어쓰기.

지도에서 장소(건물)가 놓이는 좌표(MapData.m_position)를 서로 바꿉니다. 건물 이름/장면/영입 NPC 는 그대로 함께 움직이므로
'영입된 NPC 를 그 맵에서 지운다'는 게임 규칙과 충돌하지 않고, 대사/모델도 어긋나지 않습니다.
- 은신처, 상인, HOD 전용 장소만 제자리. 시작 은신처(슈레더 스트리트 319번지) 주변도 섞음.
- 위치가 바뀌므로 각 은신처의 '갈 수 있는 장소'(m_reachableLocations)와 시작 해금 목록을 새 좌표/현재 반경 기준으로 다시 만듦.
- 은신처마다 갈 수 있는 장소가 최소 13곳 이상이 되는 배치만 사용.
검증(이 환경): 바뀐 오브젝트는 MapData 하나, 좌표 집합 동일, 은신처 18곳 목록이 좌표/반경과 일치. 장소 61곳이 이동하고 영입 장소 11곳이 모두 이동.

## 망원경 (발견 시스템 유지)
원본의 망원경 목록(m_vantagePointObservableLocations, 60곳, 각 1~4곳)은 장소 GUID 로 고정돼 있어 위치를 섞으면 먼 곳을 보여주게 됩니다.
섞은 뒤 각 망원경 장소의 목록을 새 좌표 기준 '가까운 장소'로 다시 만듭니다 (개수 유지, 은신처가 대상에 들어가는 구조 유지).
원래 어딘가에서 보이던 장소가 어디에서도 안 보이게 되면 가장 가까운 망원경 장소에 추가합니다 (이 시험에서 4곳).
은신처의 시작 해금은 원본 구조대로 '그 은신처의 망원경 목록과 동일'하게 둡니다 (평균 약 2.4곳). 반경 안 전체 해금은 하지 않습니다.
검증(이 환경): 바뀐 오브젝트 MapData 1개, 원래 보이던 장소 집합 보존, 망원경→대상 거리 중앙 325 (원본 405), 시작 해금 ⊂ 갈 수 있는 목록.
게임에서 망원경 발견이 실제로 되는지는 확인하지 못했습니다.

## 발견 연쇄 보정 (망원경이 없는 장소 문제 대응)
망원경이 있는 장소는 전략지점 44곳 + 은신처 16곳뿐입니다. 가까운 장소로만 목록을 다시 만들면, 은신처의 시작 목록 3곳이 모두 망원경 없는 장소가 되어
연쇄가 끊기는 은신처가 생깁니다 (시험 배치에서 16곳 중 3곳, 반경 안에서 못 밝히는 장소 합 315곳).
그래서 은신처별로 '시작 목록에서 출발해 반경 안 장소를 방문하며 밝히는 연쇄'를 계산해,
 - 시작 목록에 방문 가능한 망원경 장소가 없으면 가장 가까운 망원경 장소를 시작 목록에 추가하고
 - 반경 안의 원래 발견 가능했던 장소를 못 밝히면 연쇄 안의 가장 가까운 망원경 장소 목록에 추가합니다.
검증(이 환경, 시드 11개): 끊기는 은신처 0곳, 반경 안에서 못 밝히는 장소 0곳, 시작 해금 == 은신처 망원경 목록, 목록 최대 증가 5개.

## 시작 목록: 갈래마다 이어지게 (원본 규칙 재현)
원본 데이터의 은신처 시작 목록은 항목 43개가 모두 일반 장소이고 41개가 망원경 장소이며, 갈래 사이 각도는 중앙 94°로 서로 다른 방향이었습니다.
같은 규칙으로 각 은신처의 시작 목록을 '반경 안의 가까운 망원경 장소 12곳 중, 방향이 가장 다양하게 갈라지는 k곳'으로 고릅니다 (k = 원래 목록 개수).
그래서 한 갈래만 따라가도 다음 장소가 밝혀지고, 한쪽 방향 장소가 망원경이 없어 막히는 일이 없습니다.
검증(이 환경, 시드 13개): 갈래 43개 모두 혼자서 다음 장소를 밝힘(막힌 갈래 0), 망원경 없는 시작 항목 0, 반경 안 못 밝히는 장소 0,
갈래 간 최소 각도 47~80°, 시작 해금 == 은신처 망원경 목록. 먼 연결(700 초과)은 원본 최대 661 대비 시드당 1~6개/약 160개.
