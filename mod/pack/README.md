# Into the Dead: Our Darkest Days - 통합 수정 팩 (이 폴더만 받으면 됩니다)

게임 업데이트(2026-10-27, 생존자 Jett/Julie/Norman 추가)에 맞춰 만든 통합 도구. 이 폴더의 파일 전부를 **같은 폴더**에 두세요.

## 적용 (게임/스팀을 끈 상태에서)
- `run_all.bat` 더블클릭 -> Y -> 완료. (또는 `py -3 apply_all.py "<AssetBundles 경로>" [--seed 숫자]`)
- 새 게임 시작 전에만 실행하세요. 지도 위치가 매번 새로 섞이므로 진행 중인 세이브에는 쓰지 마세요.
- 게임이 업데이트될 때마다 같은 파일로 다시 실행하면 됩니다. 업데이트된 파일을 자동으로 새 원본으로 인식합니다.
- 되돌리기: `restore_all.bat` (모든 수정을 원본으로 복원, 바이트까지 동일)

지도 섞기 규칙: 은신처/상인/HOD/치프웨이즈(스토리) 장소는 제자리, 망원경이 장면에 없는 장소(세인트 버나뎃 병원, 수처리장)는 발견 연쇄에서 제외,
시작 은신처의 시작 해금은 서로 다른 방향의 진짜 망원경 장소로 구성, 반경 안 장소를 빠짐없이 밝힐 수 있게 보정.
영입 장소 섞기는 철폐했습니다 (영입 생존자의 원래 장소 NPC가 지워지는 게임 규칙 때문).

## 옵션 (명령줄)
`--seed N` 지도 시드 / `--vale random|crossbow|s12riot|none` 미스터 베일 신규 판매 품목 순서 (기본 random: 첫 품목 석궁/샷건 50:50, `none` 이면 끔) / `--romance` 공용구역 로맨스 아이템 3명 이상 허용 / `--posts` 모든 거점에서 교역소 5곳 도달 가능 / `--trader-start 0` 상인 첫 등장을 사이클 10 -> 게임 시작부터 / `--leads 1` 탈출 퀘스트 필요 단서 수 (run_all.bat 기본 1, `--leads 3` 이면 원래대로) / `--no-shuffle` 반경만 / `--ammo 5 --inv 24 --corpse 24 --radius 1.5 --slots 2` 수치 변경 / `--restore` 복원

## 백업과 안전장치
- `AssetBundles\_mods_backup\` 에 원본을 한 번 백업하고, 항상 거기서 다시 계산합니다 (여러 번 실행해도 배수가 쌓이지 않음).
- 파일 해시로 '원본 / 지난번 결과 / 게임 업데이트로 바뀐 새 파일'을 구분합니다.
- 어느 단계든 실패하면 설치된 파일은 바뀌지 않습니다.
- 이전 빌드의 낡은 백업(`data_balancing.bak`, `data_levels.bak`, `data_levels.shufflebak`, `*.mapbak`, `*.origbak`)은 이 팩이 사용하지 않으므로 지워도 됩니다.
- `telescopes.json`: 장면에 진짜 망원경이 있는 장소 검사 결과 (빌드 6000.5.x, 2026-10-27 업데이트에서도 장면 번들이 바뀌지 않아 그대로 유효). 장면 번들이 바뀌면 자동으로 다시 검사합니다.

## 검증 (이 환경, 업데이트 후 새 파일 기준)
- 새 빌드에서 번들 읽기/수정 모두 동작, 바뀐 오브젝트는 의도한 것만 (balancing 49 = 생존자 38 + 총알 10 + 지도 스테이션 1, config 1바이트, levels = MapData 1개).
- 1회/2회 실행 동일(배수 누적 없음), 복원은 업데이트 직후 원본과 바이트까지 동일, 이전 빌드 파일로 '업데이트' 모사도 정상.
- 지도: 못 밝히는 장소 0, 망원경 없는 시작 항목 0, 치프웨이즈 원본 목록 보존. 게임 안에서의 실제 동작은 확인하지 못했습니다.

## Windows + Python 3.14 에서의 접근 위반(access violation) 대응
증상: `단계 실패: patch_balance.py (종료 코드 3221225477)` + `Windows fatal exception: access violation` + `TypeTreeHelper.py ... in read_typetree`.
원인: UnityPy 의 C 가속 모듈(UnityPyBoost)이 일부 환경(Windows, Python 3.14)에서 일부 오브젝트를 읽다가 죽습니다.
조치: 모든 스크립트가 시작할 때 가속 모듈을 끄고 순수 파이썬 읽기 경로를 사용합니다 (`read_typetree_boost = None`).
검증(이 환경): 가속 ON/OFF 로 만든 결과 파일이 balance/levels 모두 바이트까지 동일합니다. 전체 적용 소요 시간 약 27초.

## 미스터 베일 신규 판매 품목 순서
원래는 20사이클 단위 구간(20-40, 40-60, ... 180+)을 R77 권총 -> 석궁 -> S12 Riot 샷건 순으로 돌아가며 사용합니다.
품목이 열리는 이벤트(NewItemForSale)와 상점 재고가 같은 구간 조건(`Trader_MrVale_NewItemSale_*_CycleRange`)에 묶여 있어서, 이 구간 배정만 바꿉니다.
- 첫 구간(사이클 20-40)의 품목은 석궁/샷건 중 무작위(50:50)이고, 이후 구간마다 다른 쪽이 열립니다 (석궁이면 다음은 샷건, 샷건이면 다음은 석궁).
  사이클 20-40 X, 40-60 Y, 60-80 X, 80-100 Y, 100-120 X, 120-140 Y, 140-160 X, 160-180 신규 없음, 180 이후 X 상시.
- R77 권총은 이벤트도 재고도 꺼서 나오지 않습니다.
- 석궁 볼트는 20사이클부터 팝니다 (원래 40). `--vale-start 10|0` 이면 볼트는 10사이클부터.
- `--vale-start 0` (또는 10) 으로 첫 구간의 시작을 앞당길 수 있습니다: 0 = 게임 시작부터 40 미만, 10 = 10~40, 20 = 원래. 두 번째 구간(40-60)부터는 그대로입니다. 베일이 상점에 접근 가능해지는 시점(상인 해금)은 바뀌지 않습니다.
- 무작위 선택은 이 도구를 실행할 때 한 번 정해집니다 (게임 안에서 새로 굴리는 것이 아님). `run_all.bat` 을 새 게임 전에 다시 돌리면 다시 정해집니다. `--vale crossbow` / `s12riot` 로 고정 가능.
- 게임 안에서의 실제 동작은 확인하지 못했습니다 (데이터 수준 검증만).
