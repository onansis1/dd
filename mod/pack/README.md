게임 업데이트(2026-10-27, 생존자 Jett/Julie/Norman 추가)에 맞춰 만든 통합 도구. 이 폴더의 파일 전부를 **같은 폴더**에 두세요.

## 적용 (게임/스팀을 끈 상태에서)
- `run_all.bat` 더블클릭 -> Y -> 완료. (또는 `py -3 apply_all.py "<AssetBundles 경로>" [--seed 숫자]`)
- 새 게임 시작 전에만 실행하세요. 지도 위치가 매번 새로 섞이므로 진행 중인 세이브에는 쓰지 마세요.
- 게임이 업데이트될 때마다 같은 파일로 다시 실행하면 됩니다. 업데이트된 파일을 자동으로 새 원본으로 인식합니다.
- 되돌리기: `restore_all.bat` (모든 수정을 원본으로 복원, 바이트까지 동일)

## 옵션 (명령줄)
`--seed N` 지도 시드 / `--vale random|crossbow|s12riot|none` 미스터 베일 신규 판매 품목 순서 (기본 random: 첫 품목 석궁/샷건 50:50, `s12only` 이면 샷건(S12 라이엇)만 계속 판매 - 석궁/석궁 볼트/R77 없음, `none` 이면 끔) / `--romance` (명령줄 전용, 메뉴에서는 뺌) 공용구역 로맨스 아이템을 3명 이상에서도 사용 가능하게 - 연애 시도는 게임 코드가 2명만 처리하는 것으로 보여 3명 이상에서는 아이템만 소모될 수 있음 / `--romance-all` 연애의 모든 제한 해제 (정확히 2명일 때 적용. 3명 이상 허용은 `--romance` 를 같이) (가족/나이대/연애 중 조건, 호환성 속성 6종(나이대·성적 지향·실연·입냄새·연애 대상 여부·관계 단계), 성공 확률 구성 값(관계 단계별·아이템 21종)을 최대로) / `--zombie` 탐험 중 죽은 생존자가 좀비가 될 확률 50% -> 100% + 예외(첫 이탈자/좀비 아닌 것에게 죽음) 전부 해제 + 강제 좀비화. 깊은 상처 감염 좀비화는 별개 경로라 그대로. 좀비화 실제 처리는 게임 코드라 게임 내 동작은 미확인 / `--quiet-steps` 생존자가 걷거나 달려도 발소리 소음 없음 (웅크릴 때와 같게. 문/루팅/전투 소음은 그대로, 게임 내 동작 미확인) / `--hod-start` 어둠의 심연 단서 3개를 시작부터 지급 (기존 지식 얻기 동작 3개의 대상을 HoD_Lead_01~03 으로 바꾸고 비어 있는 은신처 이벤트 2개에 연결하는 시도, 게임 내 동작 미확인) / `--june-lockpick` 스필존 스킵의 스쿱 준에게 방호복 받는 조건을 칠리 콘 카르네 4개 -> 락픽 1개 (대사 문구는 그대로일 수 있음, 게임 내 동작 미확인) / `--spillzone-start` 유출구역(스필존) 단서 3개 시작부터 지급 (`--hod-start` 와 같은 방식, 게임 내 동작 미확인) / `--move-posts` 교역소 5곳을 지도 중앙부로 옮겨 모든 거점의 같은 반경 안에 교역소 1곳 이상 (`--posts` 는 모자란 거점의 반경을 늘리는 대안 방식) / `--trader-start 0~9` 상인 첫 등장을 사이클 10 -> 게임 시작부터 또는 7 / `--leads 1` 탈출 퀘스트 필요 단서 수 (run_all.bat 기본 1, `--leads 3` 이면 원래대로) / `--shuffle-shelters` (실험적) 메사냉방/치프웨이즈를 뺀 거점 16곳끼리 위치 교환 - 데이터 검증은 시드 6개로 통과했으나 스토리 충돌 여부는 게임에서 미확인 / `--no-shuffle` 반경만 / `--ammo 5 --inv 24 --corpse 24 --radius 1.5 --slots 2` 수치 변경 / `--restore` 복원

## Windows + Python 3.14 에서의 접근 위반(access violation) 대응
증상: `단계 실패: patch_balance.py (종료 코드 3221225477)` + `Windows fatal exception: access violation` + `TypeTreeHelper.py ... in read_typetree`.
원인: UnityPy 의 C 가속 모듈(UnityPyBoost)이 일부 환경(Windows, Python 3.14)에서 일부 오브젝트를 읽다가 죽습니다.
조치: 모든 스크립트가 시작할 때 가속 모듈을 끄고 순수 파이썬 읽기 경로를 사용합니다 (`read_typetree_boost = None`).
검증(이 환경): 가속 ON/OFF 로 만든 결과 파일이 balance/levels 모두 바이트까지 동일합니다. 전체 적용 소요 시간 약 27초.

## 미스터 베일 신규 판매 품목 순서
원래는 20사이클 단위 구간(20-40, 40-60, ... 180+)을 R77 권총 -> 석궁 -> S12 Riot 샷건 순으로 돌아가며 사용합니다.
품목이 열리는 이벤트(NewItemForSale)와 상점 재고가 같은 구간 조건(`Trader_MrVale_NewItemSale_*_CycleRange`)에 묶여 있어서, 이 구간 배정만 바꿉니다.
- 첫 품목은 석궁/샷건 중 무작위(50:50)이고, 이후 구간마다 다른 쪽이 열립니다 (석궁이면 다음은 샷건, 샷건이면 다음은 석궁). R77 권총은 이벤트도 재고도 끕니다.
- `--vale-start 20` (원래): 20-40 X, 40-60 Y, 60-80 X, 80-100 Y, 100-120 X, 120-140 Y, 140-160 X, (160-180 없음), 180+ X 상시. 볼트는 석궁이 첫 품목이면 20부터, 두 번째면 40부터(원래).
- `--vale-start 0|10`: **일정 전체를 20사이클 앞당긴다.** 0 -> 0-20 X, 20-40 Y, 40-60 X, 60-80 Y, 80-100 X, 100-120 Y, 120-140 X, (140-180 없음), 180+ X 상시. (10 이면 첫 구간이 10-20). 볼트는 석궁이 처음 팔리는 시점부터(석궁이 첫 품목이면 10, 두 번째면 20).
- 이전 버전은 시작 0 에서 첫 구간이 0-40(40사이클)로 길고 볼트가 사이클 10부터 석궁과 무관하게 팔려서, 석궁 없이 볼트만 보이는 구간이 있었다 -> 위 방식으로 수정.
- 무작위 선택은 이 도구를 실행할 때 한 번 정해진다. `--vale crossbow` / `s12riot` 로 고정 가능.
- 게임 안에서의 실제 동작은 확인하지 못했다 (데이터 수준 검증만).

**서서 문 엿보기 (`--peek-standing`, 일반판만)**: 서 있는 상태에서도 문 엿보기가 되게 합니다. 지금까지의 다른 옵션과 달리 `AssetBundles` 가 아니라 게임의 실행 파일 `GameAssembly.dll` 을 직접 고칩니다 (`patch_peek.py`, 7단계). 이 게임 빌드(SHA-256 `3F45B1F9…061C8`)에서만 동작하고, 다르면 아무것도 바꾸지 않고 중단합니다. 처음 쓸 때 `GameAssembly.dll.bak` 을 만들고, 옵션을 끄고 다시 적용하거나 `--restore` 하면 원래대로 돌아갑니다. 게임 업데이트나 스팀 '게임 파일 무결성 검사'가 있으면 원복되며, 업데이트 후에는 패치를 다시 만들어야 할 수 있습니다. 공유용(지도 전용) 파일은 게임 실행 파일을 건드리지 않습니다.

**장소 설명에 락픽/볼트 절단기 개수 표시 (`--lock-notes`, 일반판만)**: 맵 정보의 장소 설명 끝에 `[잠금장치] 락픽 N / 볼트 절단기 M` 문구를 덧붙입니다 (`patch_lootnote.py`, `lootnotes.json`). 방문 전 장소도, 기존 세이브도 상관없이 처음부터 보입니다. 개수는 게임 데이터에서 장소별로 뽑은 값입니다: 서랍/로커 등 아이템 잠금 루트 포인트(항상 활성) + 락픽/볼트 절단기가 필요한 문(`DoorLocked` 계열). 지식으로 여는 문과 시작부터 잠기지 않는 문은 세지 않고, 금고/철창처럼 도구 종류를 알 수 없는 잠금은 `기타 잠금`으로, 트리거로 켜지는 것은 `(조건부 추가: …)`로 따로 적습니다. 잠금이 없는 장소는 `없음`으로 표시합니다. 한국어/영어 로컬라이제이션 번들(`loc.korean`, `loc.english`)을 고치며(문자열 길이가 바뀌어 번들 안 위치도 함께 고침, 쓴 뒤 다시 읽어 검증), 백업은 `_mods_backup` 에 만들고 옵션을 끄고 다시 적용하거나 `--restore` 하면 원래대로 돌아갑니다. 한계: 시작 거점으로 고른 곳의 대체 배치(7곳)는 반영하지 않았고, 게임에서 실제로 문구가 보이는지·번들 CRC 검사가 있는지는 직접 확인하지 못했습니다. 공유용(지도 전용)은 이 파일들을 건드리지 않습니다.

`lootnotes.json` 은 게임 데이터에서 뽑은 값을 위키(ourdarkestdays.wiki.gg)의 장소 인포박스와 대조해 보정했습니다: 도구 종류를 알 수 없던 잠금 5곳(Griffith & Sons Hardware, Bowen St, Keyline Storage, US Route 93, Rodessa Substation)은 위키와 개수가 정확히 맞는 쪽으로 락픽/볼트 절단기로 분류했고, 게임 데이터에서 못 찾은 3곳(319 Schrader St 락픽 1, Elkins Family Clinic 볼트 절단기 1, Millwood Manor 볼트 절단기 1)은 위키 값을 따랐으며, Walton Taxi Depot의 추가 배치 락픽 1개는 조건부로 옮겼습니다(위키 `+2(+3)`). 위키의 `+` 표기가 무슨 뜻인지는 확정하지 못했고, 38 Irving Drive는 위키 값(락픽 1)이 맞다는 사용자 확인에 따라 락픽 1로 표시합니다. 위키는 사람이 편집한 자료라 틀렸을 수 있습니다.

**무기 작업대 총알 1레벨부터 (`--ammo-all-levels`)**: 무기 작업대(WeaponsBench)는 레벨마다 만들 수 있는 레시피 목록을 따로 가집니다(기본: 1레벨 권총 총알, 2레벨 +리볼버/샷건, 3레벨 +소총/돌격소총). 이 목록에 빠진 총알 레시피(탄약 전문가 판 포함 10종)를 1, 2레벨 목록에 덧붙여 모든 총알을 1레벨부터 만들 수 있게 합니다 (`patch_ammolevel.py`). 목록 길이가 늘어 그 오브젝트가 192바이트 커지므로 뒤쪽 오브젝트 위치를 함께 옮기고, 쓰기 전에 다시 읽어 다른 오브젝트가 한 바이트도 바뀌지 않았는지 확인합니다. 재료, 작업 시간, 특성 조건은 그대로입니다. 일반판 옵션이며 `--restore`/옵션 끄고 재적용으로 원복됩니다. 게임에서 실제로 만들 수 있는지는 직접 확인하지 못했습니다.

**소탕한 거점 다시 안 차게 (`--keep-cleared`): 제거됨.** 앱에서 이 항목을 뺐습니다. 이전 빌드로 적용해 둔 경우 새 빌드로 적용/되돌리기를 하면 `GameAssembly.dll`의 이 패치는 원래대로 되돌려집니다(`patch_cleared.py`는 되돌리기 전용으로만 남아 있음).

**맨손 처형 효과음을 모든 생존자에게 (`--unarmed-sound`, 일반판만)**: 맨손 스텔스 처형 3종(기본 맨손/무술/브루탈)의 효과음 에셋은 '현재 생존자가 허드슨/하오/이사야인가' 조건이 참일 때만 소리를 냅니다(애니메이션 클립이나 캐릭터 프리팹에는 소리 이벤트가 없음). 그래서 특성 랜덤으로 다른 생존자가 무술/브루탈 처형을 해도 처형 순간 소리가 안 났습니다. 이 옵션은 그 3개 조건을 data_config 의 '항상 참' 조건(`ReturnTrueCondition`)으로 바꿉니다. 효과음 이벤트 하나에 타격음과 목소리가 같이 들어 있고 목소리는 생존자의 `CharacterType` 값으로 고르므로, 처형하는 생존자 자신의 목소리로 나는 것으로 보입니다(제트/노먼은 목소리 없이 타격음만). **게임이 처형 때 CharacterType 을 실제로 넣는지는 코드로 확정하지 못했고 게임에서도 아직 확인하지 못했습니다.** 같은 방식으로 무술/브루탈 무기의 크리티컬 킥·무릎, 다운 처형 02/03(하오/이사야 조건) 효과음 5개도 고칩니다(총 8곳. 크리티컬 '중간'은 이 게임 데이터에서 쓰는 무기를 찾지 못했으나 함께 바꿈). 같은 조건 객체를 쓰는 다른 에셋은 건드리지 않도록 값 검색이 아니라 확인된 위치만 고칩니다. 무술/브루탈 NPC 무기도 같은 처형을 쓰므로 NPC 처형에서도 소리가 날 수 있습니다(확인 못 함). 번들이 블록 압축이라 바뀐 블록 3개만 다시 압축하고 블록 표를 고쳐 `data_visual`(약 530MB)을 다시 씁니다. 위치의 원래 내용이 예상과 다르면(게임 업데이트) 아무것도 쓰지 않고 중단합니다. 번들 CRC 검사 여부는 확인하지 못했습니다. 되돌리기는 원본 백업 복원입니다.

**모든 생존자 시작 특성 랜덤 (`--random-traits`, 일반판)**: 이름 있는 생존자 38명은 정의(`SurvivorData`)의 시작 특성에 양성(`Trait+…`) 1개와 음성(`Trait-…`) 1개를 가집니다. 고정되지 않은 칸의 양성끼리, 음성끼리 모아 시드로 섞어서 다시 나눕니다(`patch_traits.py`; 특성 종류와 개수는 그대로고, `--seed`를 주면 같은 결과). 참조(PathID)만 바뀌므로 오브젝트 크기는 그대로입니다. 스토리와 얽힌 12칸은 고정합니다: 그 생존자를 지정해 그 특성을 치료/부여/검사하는 스토리 액션·조건이 있는 칸, 영입 데이터가 가리키는 칸, 파일럿(쿠퍼)·체프웨이즈 직원(오토)·시나리오 모드 전용 특성. 현재 고정: Bowman(+Marksman, -Unmoored), Cooper(+Pilot), Hector(-Insomniac), Hudson(-Agoraphobia), Issac(+Counselor, -Pacifist), Michelle(-HarshReminder), Otto(+ChiefwaysEmployee), Penny(-Haunted), Robbie(-Talkative), Sebastian(-Jaded). 맨손 격투 능력은 특성이 아니라 생존자에게 지정된 맨손 무기(`m_innateEquipment`: Hao=`SurvivorUnarmedMartialArts`, Isaiah=`SurvivorUnarmedBrutal`, 나머지=`SurvivorUnarmed`)가 만들기 때문에, `Trait+MartialArtist`를 받은 생존자에게 MartialArts 무기를, `Trait+ProfessionalWrestler`를 받은 생존자에게 Brutal 무기를, 둘 다 없으면 기본 무기를 함께 줍니다(특성을 잃은 하오/이사야는 기본 무기로). 영입 데이터(`RecruitmentData`)나 시작 생존자 쌍에 한 번도 나오지 않는 생존자(게임에서 얻을 수 없는 Jett/Julie/Norman)는 섞기에서 빼서 그들에게 특성이 가 낭비되지 않게 합니다. `MI_`/`State_`(개 애호가, 시작 경험치 등)는 건드리지 않습니다. 한계: 새 게임과 새로 영입하는 생존자에게만 적용되고 진행 중인 세이브의 특성은 그대로입니다. 스킬 트리가 같은 특성을 주는 칸과 겹치는 경우, 섞인 특성과 스토리 이벤트('Give_…')가 같은 특성을 또 주는 경우의 동작은 게임에서 확인하지 못했습니다. 같은 특성(예: 슬러거)이 원래부터 여러 명에게 있던 것은 그대로 여러 명에게 갑니다.

**모든 생존자 스킬 트리 티어별 랜덤 (`--random-skills`, 일반판)**: 생존자마다 스킬 트리(`SkillTreeData`)는 4개 티어이고 티어마다 선택지가 1~2개 있습니다. 티어끼리(1티어는 1티어끼리 …) 시드로 섞어서 다시 나눠줍니다(`patch_skills.py`; 선택지가 1개인 티어는 그 구조가 그대로 따라감). 16바이트 GUID 값만 옮기므로 오브젝트 크기는 그대로고, 그 생존자가 이미 가진 시작 특성이나 같은 트리의 다른 티어와 겹치는 선택지가 적게 가도록 여러 번 시도해 가장 좋은 것을 고릅니다(`--random-traits`와 같이 쓰면 섞인 시작 특성 기준). 건드리지 않는 것: 파일럿용 임시 트리(`TEMP`), 비어 있는 트리, 얻을 수 없는 생존자(Jett/Julie/Norman)의 트리, 스토리 액션·조건이 그 생존자와 그 특성을 지정한 티어. 새 게임과 새로 영입하는 생존자에게만 적용되고, 진행 중인 세이브에서 이미 고른 스킬은 그대로입니다. 한계: 스킬이 특성 참조라서 능력이 캐릭터에 묶인 것(맨손 무기처럼 데이터가 아닌 것)은 따라가지 않을 수 있고, 게임에서 확인하지 못했습니다. `--seed`가 있으면 특성과 같은 시드를 씁니다.

**무술가/프로레슬러 특성 보유자 4티어 맨손격투 전문가 보장 (`--martial-h2h`, 일반판)**: 맨손 암살(스텔스 처형)은 두 가지로 정해집니다 — 허용은 스킬 `Trait+HandToHandExpert`(스텔스 처형 조건 `StealthExecution_OrCondition`이 '이 특성이 있다'를 봄), 동작은 그 생존자의 맨손 무기(기본/`MartialArts`=하오/`Brutal`=이사야)의 처형 데이터. 이 옵션은 `Trait+MartialArtist`(하오의 원래 특성) 또는 `Trait+ProfessionalWrestler`(이사야의 원래 특성)를 가진 생존자의 스킬 트리 4티어에 `HandToHandExpert`가 오도록 4티어 항목을 맞바꿉니다(`patch_skills.py`의 `h2h`). `--random-traits`로 특성이 섞였으면 섞인 특성 기준이고, `--random-skills`와 같이 쓰면 섞은 뒤에 맞추며, 혼자 쓰면 스킬 트리는 그대로 두고 이것만 보정합니다(`noshuffle`). 4티어가 스토리로 고정된 경우는 건너뜁니다. 새 게임/새 영입에만 적용되고 게임에서 확인하지 못했습니다.

**오토 영입 방호복 -> 락픽 (`--otto-lockpick`)**: 스필존 관제실(`Spillzone_16_ControlRoom_01_NPCI_01` 대화)에서 오토를 영입하려면 방호복(초록/오렌지/흰색/노랑/노라 5종 중 장착하지 않은 것)을 건네야 합니다. 이 옵션은 건네기 선택지의 조건 두 곳(재방문 노드, 선택 노드)을 data_config 의 `HasInBackpack_Lockpick`(배낭에 락픽 1개 이상)으로 바꾸고, 색별 분기 5개 중 초록 분기만 락픽 조건으로 열고 나머지 4색은 항상 거짓 조건으로 닫고, 초록 분기가 소모하는 아이템을 락픽 1개로 바꿉니다(대화 노드 3개 + 소모 동작 1개, 크기 변화 없음). 방호복 조건 객체 자체는 여러 곳에서 공유하므로 건드리지 않습니다. 대사 문구는 번역 파일에 있어서 바꾸지 않았고 방호복이라고 나올 수 있습니다. 게임에서는 아직 확인하지 못했습니다.

**GUI(일반판) 정리**: 항목이 많아져 창이 화면 아래로 잘리던 문제를 고쳤습니다. 창 높이를 화면에 맞추고(낮은 화면에서는 배너를 줄임), 게임 폴더/항목 영역은 마우스 휠로 스크롤하며, 시드/적용 버튼/상태/로그는 아래에 고정됩니다. 항목은 지도 / 물자·거래 / 생존자 / 작업대·표시 / [시도] / 게임 파일 직접 수정 으로 묶었고, 항목 위의 `전체 선택` / `전체 해제` 버튼으로 모든 체크박스를 한 번에 켜고 끌 수 있습니다(게임 실행 파일·효과음 번들을 고치는 항목도 같이 켜지니 주의).

**스킬 섞기에서 아이작(Issac) 제외**: 아이작은 `Birds of Prey`(킹사이드) 탈출 플랜에서만 영입되는 생존자라 평소 플레이에서는 나오지 않아, 그 칸에 간 스킬이 낭비됩니다. `--random-skills`(와 `--martial-h2h`)는 아이작의 스킬 트리를 건드리지 않고 원래대로 둡니다(그래서 제2의 천성(`Trait+SecondNature`)은 원래처럼 아이작에게 묶여 나오지 않습니다). 나머지 스킬은 모두 나오는 생존자에게만 갑니다.

**스테이션 휠 특기 강조 (`--wheel-gold`, 일반판 전용, 이 게임 빌드 전용)**: 은신처에서 F 길게 눌러 여는 스테이션(작업) 휠에서, **지금 조작 중인 생존자의 특기 특성(스테이션 정의의 `m_relevantTraits`)과 맞는 작업 칸의 아이콘을 금색**으로 칠합니다. 나쁜 특성(`Trait-BadCook`, `Trait-Talkative` 등 휠 목록에 들어 있는 9개)은 겹쳐도 세지 않고, 자리가 꽉 찬 칸은 원래의 회색을 그대로 둡니다. 게임에는 이런 기능이 없어서 새 코드를 넣었습니다.
 - 구현: `GameAssembly.dll`에 코드를 넣을 새 실행 구역 `.itdx`(4096바이트: 파일 끝 + 구역 헤더 + SizeOfImage + 구역 수)를 추가하고, 그 안에 동굴 코드 둘(특기 겹침 계산, 색 선택)과 부정 특성 표를 씁니다. 후크는 `ShelterStationManager.GoToStationWheel`(RVA 0xA59546)과 `StationWheelIconUI.PopulateBuilt`(0xD7277E) 두 곳이고, 새 코드는 `call` 없이 점프로 들어갔다 나옵니다. 컨텍스트 객체의 빈 패딩(+0x24)에 0/1 플래그를 씁니다.
 - 안전장치: 이 게임 빌드(SHA-256 `3F45B1F9…`)에서만 동작하고 후크 앞뒤 20바이트가 다르면 쓰지 않습니다. `GameAssembly.dll.bak`(원본 백업)을 만들고, 쓴 뒤 읽어서 확인하고, 되돌리기는 후크 → 코드 → 구역 순서입니다(코드가 있는 동안 구역만 되돌리지 않음). 알 수 없는 상태는 건드리지 않습니다.
 - 개발 중 도구(`itd_space_patch.py` + `itd_goldicon_patch.py` v2)로 이미 적용한 파일도 알아보고(마지막 단계로 인식, 중간 시험 단계는 마지막 단계로 옮김), `--wheel-gold` 를 끄고 적용하면 되돌립니다.
 - 이 항목을 켜면 파일 크기가 4096바이트 늘어나는데, 문 엿보기(`--peek-standing`) 도구의 '원본 판정'도 이를 알아보도록 고쳤습니다(적용 순서 무관, 합성 DLL로 시험).
 - **스팀 업데이트나 '게임 파일 무결성 검사'를 하면 이 수정은 지워집니다.** 게임이 업데이트되어 바이트가 달라지면 적용을 거부하므로 계획(후크 위치)을 새로 만들어야 합니다.
 - 게임에서 확인된 것: 은신처에서 휠을 열었을 때 자리가 남은 칸 중 내 생존자의 특기와 맞는 칸만 금색으로 나옵니다. 확인하지 못한 것: 모든 스테이션/모든 생존자 조합, `IsTraitValid` 필터(UI의 '관련 특성' 표시)와의 미세한 차이(단순 GUID 겹침만 봄), 다른 모드와의 충돌.
